# TypeScript refresh tracker

<!-- typescript-refresh: last-verified=2026-11-04 typescript-version=7.0 -->

Living record of `typescript-guidance` (refresh mode) sweeps — the
per-facet, per-source state a run diffs against, so each sweep reports what
**changed** since the last one instead of rediscovering the whole toolchain
from scratch. Updated **in place** on every run, never as a new dated file.

`typescript-version` in the header records the newest **upstream**
TypeScript release the last sweep verified against — deliberately distinct
from `package.json`'s own `typescript` devDependency pin, which this
tracker exists to check against, not restate. The two numbers disagreeing
is not a bug in the tracker; it's the finding.

First sweep 2026-11-04, re-swept the same day (`/customize` second pass). Newest upstream verified: TypeScript 7.0 (announced 2026-07-08) and 7.1 Beta (2026-10-20). TypeScript 7.0.2 exists: the microsoft/TypeScript tag page shows 20 Aug (year inferred from the page); a lint-agent claim of 2026-07-16 came from an issue and is not supported.

## Outstanding drift

| TypeScript 7.x upgrade                                                                | **Not blocked, but not ready.** typescript-eslint supports `>=4.8.4 <6.1.0` and does not mention 7. TS 7.0 ships no compiler API and publishes `@typescript/typescript6` (re-exports the 6.0 API) for tools that need it; 7.1 Beta adds a new API. Adopt 7 only through that alias route or after typescript-eslint support. `typescript` is now pinned `~6.0.3` (applied 2026-11-04) so a 6.1 cannot drift out of typescript-eslint's range. |
